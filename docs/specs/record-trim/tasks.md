## M1：保存新录音时自动裁切首尾静音 ✅ 2026-10-25

- [x] audio：抽出公共 `rms_envelope`，aligner 改用同一 helper（行为不变）
  - 验证：全量 pytest 中 aligner 的句界/换气口用例保持通过
- [x] recorder：`find_sound_bounds`（自适应阈值 + 首尾都要求持续 ≥50ms，返回首末
      有声时刻）、wav 实际时长探测（含未写完 wav 头的兜底）、`trim_silence`
      （0.2s/0.5s 余量、原子替换、失败保留原文件、整段静音抛错）
- [x] recorder：stop 等整条 `parec | ffmpeg` 进程组退出后才返回（原先只等 bash；
      立刻读文件会读到未写完的 wav 头和半截音频）
  - 验证：真实采集测试音，stop 返回后 1 秒内文件大小 10 次采样均为 589902 字节，
    进程组已退出（修前同一时刻读到 524288 字节的未收尾文件）
- [x] main：保存路径先裁切再入库；整段静音返回 400 并清文件；`duration` 用成品
      实际时长
- [x] 单测 `test_recorder.py` 9 项：首尾边界、整段静音、前导/尾部 10ms 点击不当作
      起止、安静录音（峰值约 -40dB）、本来没有空白时不重编码、wav 头占位值兜底
- [x] **验证（全量测试）**：`93 passed in 2.34s`
- [x] **验证（真实录音副本）**：复制《Young for you》原录音（200.62s，首 3.3s、
      尾 19s 数字静音）跑裁切
  - 证据：成品 178.975s（ffprobe 178.975011）；开头 0.2s 后进入音乐，末个有声样本
    在结尾前 0.51s、最后 0.45s 全零；对照原文件确认首尾内容未被削掉
- [x] **验证（真实服务 API）**：隔离服务走 start → 播放 8s 素材 → stop 保存，
      保存的 `duration` 取自裁切后成品；纯静音录音 stop 返回 400「没有录到声音」
      且文件已清理
  - 说明：测试时默认 sink 上有 Chrome 持续播放（`pactl` 可见 sink-input），无法做
    「数字静音首尾」的边界级真机断言；边界验证由上面的合成单测 + 真实录音副本承担
- [x] 文档：mvp spec 的功能范围补一行，指向本 spec
