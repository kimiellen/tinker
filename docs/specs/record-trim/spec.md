# record-trim —— 新录歌曲自动裁掉首尾静音 spec

## 背景与目标

录新歌的实际操作顺序是：先在 tinker 里点录制，再到浏览器里播放网易云；
结束时先停音乐，再回 tinker 点停止录音。于是录音开头（点录制到起播）和结尾
（停播到命名、点保存）各有一段静音。实测存量《Young for you》开头静音 3.3s、
结尾静音 19s，歌曲列表的时长也因此偏大。

目标：停止并**保存**新录音时，自动裁掉首尾空白，歌曲时长按裁切后的实际音频为准；
学习页起播即音乐，结尾不拖着长静音。

## 关键约束

- 只对**以后新录的歌**生效（2026-10-25 用户确认）。存量歌的逐句时间戳、唱录偏移
  都基于原文件，重新裁切会让它们整体错位。
- 裁切后开头保留 0.2s、结尾保留 0.5s（2026-10-25 用户确认）：既基本感觉不到空白，
  又不会削掉第一个音或尾音的自然收尾。
- 判定只看系统内录音频本身：25ms 窗 / 10ms 步长 RMS 包络，阈值取
  「最响帧 -45dB」与「-60dB」中的较大者；取首段持续 ≥50ms 的有声帧到最后一个
  有声帧。monitor 在无声时采到的是数字零，不需要更复杂的噪声模型。
- 整段静音（确实没录到声音）拒绝保存并删除文件，不存一首纯静音的歌。
- 裁切本身失败（ffmpeg 异常等）**不丢录音**：保留原文件继续保存；只有检测结论是
  「整段没有声音」才拒绝。
- 停止时必须等采集管道（`parec | ffmpeg`）完全收尾再读文件：bash 退出不代表 wav
  已经写完，此时裁切会按半截文件算边界，把真实尾音和结尾静音一起丢掉。

## 选定方案及理由

**numpy 能量包络找边界 + ffmpeg 按边界精确重编码 wav。**

- 与 aligner 的换气口检测共用同一套能量包络，阈值口径一致、代码不重复，且可以
  脱离真实声卡用合成音频做单测。
- 不用 ffmpeg `silenceremove` / `silencedetect`：滤镜链的阈值语义黑盒、解析 stderr
  脆弱；项目已经有 numpy 解码与包络工具，复用成本更低。
- 裁切只在保存路径执行（丢弃不裁，避免白解码一遍）：先检测边界，再用一次 ffmpeg
  从原始 wav 精确重编码为 PCM wav（无损），落盘用临时文件原子替换。
- `Song.duration` 一律按裁切后文件的实际帧数写入，不再用墙钟时长（墙钟还包含在
  命名弹窗里停留的时间，正是尾部静音的主要来源）。

## 非目标

- 不给存量歌曲提供重新裁切入口（会打乱已对齐的逐句时间戳与唱录偏移）
- 不做静音阈值/余量的用户可调界面
- 不改变「先点完成录音 → 弹窗命名 → 点保存才真正 stop」的现有交互
  （尾部静音由裁切兜底）
- 不处理跟唱成品（takes）的麦克风前后静音
