## M4：跟唱评估 ✅（2026-10-21 完成）

- [x] 跟唱录音（单句/整首）API
- [x] librosa 音高提取：原唱 vs 跟唱，时间对齐
- [x] 逐句评估：调偏高/偏低、抢拍/拖拍，产出明确到句的文字反馈
- [x] 前端评估界面（按 UI 定稿 ④）：音高曲线叠加 canvas + 逐句反馈卡
- [x] **验证**：故意唱跑调一句，评估结果能指出该句问题
  - 证据：用 ffmpeg 造跟唱样本（第 3 句升 3 个半音、第 10 句提前 0.6s，其余原样），整首评估 27 句中**仅**标出第 3 句「偏高 3.0 个半音」与第 10 句「抢拍」，零误报；单句模式（line_index=3，仅 3.8s 录音）同样判出偏高；错误路径 400/400/404 通过；evaluator 单元测试 11 项（节奏对齐/音高偏差/静音/全局偏移中位数）；drawPitch/renderEval 用真实评估数据在 node 中无异常渲染
  - 算法说明：节奏用逐句有声段互相关（而非开口时刻——窗口会切掉抢拍）；全局偏移取各句中位数，单句与之比较判抢拍/拖拍
  - 踩坑记录：ffmpeg 变调须 `aresample` 回原采样率，否则 concat 时音高被抵消

## M5：连读/吞音标注改本地规则引擎 ✅（2026-10-21 完成）

背景：M3 的 LLM 标注实测准确率仅三四成且大量漏标（wanna‿drive 这类尾元音+头辅音被错标连读，jeans‿and 这类真连读漏标）。规则是确定性的，改本地实现。

- [x] 引入 cmudict（纯数据包，无重依赖），音素级规则引擎：连读（尾辅音+头元音 / 尾元音+头元音滑音 / 尾 r+头元音）、吞音（尾爆破音+辅音头失去爆破 / 元音间非重读 t 闪音）
- [x] annotate 改造：LLM 只做翻译；连读/吞音走规则引擎；无 API key 时仍出标注、翻译留空
- [x] 规则引擎单元测试（每条规则正反例）；annotate 测试同步更新
- [x] **验证**：两首已有歌曲重标注，逐条人工核对连读/吞音准确率显著高于 LLM 版
  - 证据：Young for You 前 16 句与 Twinkle 前 12 句逐条人工核对零错误（含 your‿apartment / other‿in 的 r 连读、my‿age / how‿old 滑音、said/feed/what 等失去爆破、little tt 闪音；wanna‿drive / said‿the 等 LLM 版误标全部消失，jeans‿and / but‿I 等漏标全部补回）；单元测试 38 项通过（phon_rules 12 项正反例）；无 key 状态下两首歌标注均 done、翻译留空待补
  - 踩坑记录：ARPABET 元音表漏 EY 导致 age 类词判定错误（单测抓住）；词尾 ER 是 r 化元音需按 r 连读处理；所有格 's 词典缺失需回落词干补 S/Z

## M6：整首连播 + 高亮跟随（2026-10-21 spec-change，替代逐句 seek 连播）

背景：句间边界已是能量低谷切分且无缝，但旧交互每句结尾回退 seek 接下一句，timeupdate 约 0.25s 延迟导致下一句开头被重播（用户反馈句首/句尾重复发音）。改为整文件连播、按时间戳高亮，零 seek。后端零改动，边界不动。

- [x] `lineAtTime(lines, t)` 纯函数：t 落在哪句返回哪句下标，句间间隙（间奏）返回 -1；node 单测
- [x] `timeupdate` 重写：默认仅高亮跟随不 seek；仅单句循环开启时越过句尾跳回句首；曲末暂停
- [x] 控制键行为保留：播放/暂停、上/下一句 seek 句首（保持播放状态）、单句循环开关、0.5x/0.75x/1x 变速、点句起播、快捷键
- [x] **验证**：node 单测纯函数与播放状态机分支；启动服务确认学习页与音频接口正常；浏览器实播一首歌确认无重复发音
