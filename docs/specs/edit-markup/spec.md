# edit-markup —— 逐句手动修改连读/吞音标注 spec

## 目标

规则引擎的自动标注偶尔不符合歌手实际唱法，需要人工修正入口：学习页每句歌词
右下角加「✏️ 修改标注」按钮，弹窗内编辑标记文本，保存后学习页就地更新该句。
使用人是家长（帮孩子修正），不是孩子本人。

## 标记语法（面向用户的唯一形态）

- **连读**：两个词之间用 `-` 连接，如 `But-I know the sun will shine for-us`
- **吞音**：被吞的字母用 `^` 包裹，如 `I wan^t^ you to kee^p^ your dream`
- 弹窗打开时，文本框预填当前标注（自动生成的或上次手动保存的）转换出的标记文本

## 选定方案及理由

**数据模型：每句只存 `marked` 标记文本，废弃 `liaison`/`swallow` 结构化字段**
（2026-10-23 用户选型）。单一事实源，不存在"标记文本与结构漂移"问题；
前端渲染时现场解析标记文本，后端只做生成与校验。

- 生成（规则引擎结果 → 标记文本）：后端 Python，分句标注（annotate）时写入
  每行 `marked`；与前端解析只有一份语义约定（上方语法），各自实现。
- 校验（保存时）：剥掉全部 `-`/`^` 标记后的规范化词序列必须与原句
  `line.text` 一致——防止误删字母把歌词改坏，也挡住原文自带 `-` 的边界情况；
  不一致返回 400 与原因。校验在后端，可进 pytest。
- 「恢复自动标注」：后端按规则引擎现场重算该句标记文本返回给弹窗（不落盘），
  用户再点保存确认——避免误触直接覆盖手动成果。
- 存量迁移：此前不存在手动标注，启动时对缺 `marked` 的已标注歌曲重跑规则引擎
  生成落盘即可，无数据可丢。

## 界面

- 每句卡片底部一行：左侧沿用现有提示标签（︶ 连读 / ✂ 吞音 x），右侧小的
  幽灵风格「✏️ 修改标注」按钮；无标注的句也显示按钮（可从零手写标注）。
- 弹窗：标题带句号；上方小字显示原句供对照；中间多行文本框；下方一行语法
  提示；按钮区 [↺ 恢复自动] [取消] [保存]；校验失败在弹窗内红字提示，不关闭。
- 弹窗打开期间屏蔽学习页快捷键（空格/方向键），避免与输入冲突。
- 只影响学习页展示；跟唱评估不消费标注，不受影响。

## 非目标

- 不做弹窗内实时预览（用户已明确：保存后直接在学习页看效果）
- 不允许借编辑修改歌词文字本身（校验强制词序列不变）
- 不做标注修改历史/撤销
