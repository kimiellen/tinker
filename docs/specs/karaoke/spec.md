# karaoke —— 卡拉OK（伴奏分离 + 跟唱回放）spec

## 目标

让孩子跟着"去掉人声"的伴奏唱，并且能把这次跟唱录下来回放（不打分）。
原唱随时可切回来对照。

## 关键约束

- 音源是网页版网易云内录的系统混音（约 128kbps 流），不是母带——分离质量有上限，
  人声残留、伴奏金属音都正常，目标是"孩子能跟得上"，不是"官方伴奏级"
- 本机只有 CPU（Ryzen 7 5800H，8C/16T；`nvidia-smi` 不可用、无 /dev/nvidia*），
  无 GPU 加速
- 跟唱录音用系统默认输入源（`parec @DEFAULT_SOURCE@`）；**外放时麦克风会录进伴奏
  回声**，所以界面必须提示戴耳机
- 破坏操作不留孤儿：删除歌曲时伴奏与跟唱录音一并删除

## 选定方案及理由

**伴奏生成：Demucs htdemucs（`--two-stems=vocals`）**，2026-10-24 本机实测：

- 3 分 25 秒（200.6s）的歌：独立探针 66s、接进服务后实测 73s，约 2.7~3.3x 实时；
  首次还需下载 80MB 模型（HuggingFace `adefossez/HTDemucs`），之后离线可用
- 质量佐证：同一首歌，人声轨能被 faster-whisper 完整转写全部歌词；伴奏轨只能转出
  "You You You" 这类幻觉——歌词已不可辨认，说明人声基本去净
- 代价：torch 环境约 1.1GB 磁盘（torch 2.14.1+cpu / torchaudio 2.11.0+cpu /
  demucs 4.1.0 在 Python 3.14.8 上实测可用），分离跑在子进程里，结束即释放内存

否决项：
- **ffmpeg 中置声道消除**：零依赖秒出，但只削立体声中置，人声和贝斯/鼓一起被削，
  效果明显不如 AI 分离
- **ONNX 版 MDX-Net**：环境体积小，但 Python 3.14 兼容性与速度都需重新验证，
  工具链是第三方 UVR 系，收益不确定
- **手动找官方伴奏版录入**：音质最好但只有部分歌有，是补充手段不是方案

**生成时机：首次需要时用户触发，后台单任务队列，结果缓存**

一首歌约 1 分钟；录完就全量预处理会大量空跑没学过的歌，所以只处理真正要用的歌。
缓存到 `data/stems/`，之后秒开；生成期间继续播原唱，不让用户干等。

**播放：学习页加"原唱 / 伴奏"切换，保留播放位置与播放状态**

与现有整文件连播模型一致：切源时记住 currentTime，切完 seek 回去继续播。

**跟唱录音：伴奏播放时同步录麦克风，停止后按启动偏移与伴奏混成一个 mp3**

成品单文件（像 KTV 成品），回放/删除都简单，不需要前端双轨同步。偏移由前端在
起播时与录音启动时各记一次同机时间戳得出，误差在 100ms 内，娱乐用途无感。
存档：`data/stems/{song_id}/no_vocals.mp3`、`data/takes/{song_id}/{take_id}.mp3`，
跟唱元数据（起始位置、时长、偏移）落在 `songs.json` 的 takes 里。

## 功能范围

- 伴奏生成：点击触发、状态展示、失败可重试、结果缓存、删除歌曲时清理
- 学习页原唱/伴奏切换（未生成时先播原唱并显示进度提示）
- 跟唱录制（从当前播放位置起唱）、与伴奏混合保存、回放、删除

## 非目标

- 跟唱评分/打分（2026-10-24 已决议不做，见 mvp/spec.md）
- 人声/伴奏分轨音量调节、伴唱引导声（需要时重跑分离即可补做）
- 乐器多轨分离（只做 vocals / no_vocals 两轨）
- 多个伴奏任务并发、自动重试
- 伴奏或跟唱成品导出到应用外
