# takes-library —— 我的唱录（唱录库）spec

## 目标

歌单首页的「录一首新歌」旁边加一个「🎧 我的唱录」入口，跨歌曲陈列孩子录过的所有
跟唱成品。每条唱录默认叫「歌曲名-时间」，可以重命名、回放、删除（二次确认），
还可以拖动排序，把最喜欢的唱录排到前面。使用人是孩子本人（找自己唱过的歌来听）
与家长（改名、清理）。

## 关键约束

- 唱录本体仍归属歌曲：元数据在 `songs.json` 的 `takes` 里，文件在
  `data/takes/{song_id}/`；删歌连带删唱录的既有约束不变。
- 单机单用户、零新依赖；沿用现有奶油底 + 珊瑚/青绿的儿童风 UI 与无构建前端。
- 排序只是**陈列顺序**，不引入自动连播/播放队列（2026-10-25 用户确认）。
- 改名与顺序同步到学习页「我的演唱」，同一唱录在两处名称、顺序一致
  （2026-10-25 用户确认）。

## 选定方案及理由

**唱录元数据就地扩展：每条 take 增加 `name` 与全局 `position`，新唱录排最前。**

- 不另建 `takes.json`：唱录本来就归歌曲所有，独立索引会引入双写、删歌级联和
  「哪份才是事实」的漂移；当前规模用一份 JSON 足够（YAGNI）。
- 默认名在**录制完成时落盘**，而不是每次渲染现拼：改名后默认名要稳定，且唱录页
  与学习页共享同一个名字。旧 take 缺字段时启动时幂等补齐（无存量数据也安全）。
- 排序沿用歌单排序的全量提交：前端提交完整唱录引用序列，后端校验集合一致，
  过期列表返回冲突，避免把刚录的唱录排丢。跨歌排序需要全局序号，故 `position`
  放在每条 take 上，而不是歌曲里。
- 跨歌列表由后端聚合返回（带 `song_id`/`song_title`），前端不再拉全量歌曲自己摊平；
  播放/删除/改名沿用现有按歌曲嵌套的资源路径。
- 删除沿用现有 DELETE 与「dialog 二次确认」模式；播放沿用现有音频接口。

## 界面

- **首页**：按钮行两枚大按钮并排，窄屏自动换行。「🔴 录一首新歌」保持主按钮，
  「🎧 我的唱录」为青绿次按钮；有唱录时按钮右侧带数量小徽标。
- **唱录页**：独立全屏页（与贴歌词/学习页同级）。顶部 ← 返回、标题「🎧 我的唱录」、
  一行提示「按住左边 ⠿ 可以拖动排序」。列表条目从左到右：
  拖拽把手、唱录封面（🎤）、名称（粗体）+「来自《歌名》· 时长」、播放/暂停、
  ✏️ 重命名、🗑 删除。
- **播放中**：整卡青绿描边 + 浅青底色，播放键变暂停，卡片底部细进度条随播放前进；
  切歌/离开页面自动停播。
- **重命名**：弹窗预填当前名字，空名不提交；保存后就地更新列表（不整页刷新）。
- **删除**：弹窗显示唱录名与「删掉就找不回来了」提示，按钮「先留着 / 删掉」；
  删正在播放的条目先停播。
- **空状态**：没有唱录时显示引导——去歌单打开一首歌，戴上耳机点「🎤 录歌」。
- **学习页**：「我的演唱」列表按同一 `position` 排序，标题显示唱录名（不再显示
  「第 N 次 · 时长」），时长移到副行。

## 非目标

- 自动连播 / 播放队列（用户已确认只做陈列排序）
- 唱录导出到应用外、跨设备同步
- 按歌曲分组展示、把唱录搬到另一首歌、剪辑跟唱片段
